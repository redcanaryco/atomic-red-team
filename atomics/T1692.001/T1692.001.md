# T1692.001 - Command Message

## Description from ATT&CK

> Adversaries may send unauthorized command messages to instruct control system assets to perform actions outside of their intended functionality, or without the logical preconditions to trigger their expected function. Command messages are used in ICS networks to give direct instructions to control systems devices. If an adversary can send an unauthorized command message to a control system, then it can instruct the control systems device to perform an action outside the normal bounds of the device's actions. An adversary could potentially instruct a control systems device to perform an action that will cause an [Impact](https://attack.mitre.org/tactics/TA0105).(Citation: Bonnie Zhu, Anthony Joseph, Shankar Sastry 2011)
>
> In the Dallas Siren incident, adversaries were able to send command messages to activate tornado alarm systems across the city without an impending tornado or other disaster.(Citation: Zack Whittaker April 2017)(Citation: Benjamin Freed March 2019)

[Source](https://attack.mitre.org/techniques/T1692/001)

### Atomic Test #1: Unauthorized Modbus Write to a Protected Register

Sends an unsolicited Modbus/TCP WRITE_SINGLE_REGISTER (function code 6) command message to a target device, simulating an adversary issuing an unauthorized write to a register the source has no legitimate reason to modify. This is the ATT&CK for ICS T1692.001 pattern of sending a command message outside the normal control logic to manipulate a device's operating state.

Point `--host` at a Modbus/TCP device or simulator you are authorized to test against (e.g. a lab PLC, or a local `pymodbus` server). Sends exactly one request; performs no scanning or brute forcing.

**Supported Platforms:** Linux, macOS

**auto_generated_guid:** `8f2c1e5a-6b3d-4a7e-9c0f-1d5b8e2a4c6f`

#### Inputs

| Name | Description | Type | Default Value |
|------|-------------|------|---------------|
| host | Target Modbus/TCP device or simulator. | string | 127.0.0.1|
| port | Target Modbus/TCP port. | integer | 502|
| address | Register address to write to. | integer | 150|
| value | Value to write into the register. | integer | 255|
| path_to_script | Path to the Modbus command-message script. | path | PathToAtomicsFolder/T1692.001/src/modbus_command_message.py|

#### Attack Commands: Run with `sh`!

```sh
python3 "#{path_to_script}" --host #{host} --port #{port} --mode write --address #{address} --value #{value}
```

### Atomic Test #2: Modbus Command Message Using a Reserved/Illegal Function Code

Sends a Modbus/TCP command message using a diagnostics/reserved function code (default 8) that a typical field device does not serve during normal operation -- an ATT&CK for ICS T1692.001 pattern used to probe or trigger unexpected device behavior via an out-of-policy command message, distinct from a legitimate read/write request.

Point `--host` at a Modbus/TCP device or simulator you are authorized to test against. Sends exactly one request; performs no scanning or brute forcing.

**Supported Platforms:** Linux, macOS

**auto_generated_guid:** `3a7d9c1b-4e6f-4b2a-8d5c-7f1a3e9b2c5d`
